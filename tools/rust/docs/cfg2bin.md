# cfg2bin

Convert TOML or JSON configuration files to binary TPRM payloads and
sequence blobs.

---

## Overview

`cfg2bin` reads a typed TOML or JSON configuration file and serializes each
field to little-endian binary. With `--fulluid` the output is a **format A
v3 component payload**: the serialized bytes behind a 20-byte prelude
(magic `APV3`, version, payload size, target fullUid, layout hash,
CRC-32) that every reader verifies before loading. Without it the output
is the raw serialization -- the form sequence binaries and generic blobs
use.

The layout hash is the CRC-32 of the canonical field spec
(`name:type:size:offset;` per leaf in declaration order, arrays as
`name:array:total:offset;[type:sizexN]`, closed by a `|size:total`
terminator). Offsets pin the byte layout: templates that serialize the
same fields at different positions -- packed vs padded arrangements
included -- stamp different hashes. Nested value tables inline their
leaves at running offsets, so nesting does not change the vocabulary.

## Options

```
cfg2bin --config <file> [--output <file>] [--fulluid <hex>]
cfg2bin --batch <dir> --output <dir>
```

| Option                     | Description                                                                            |
| -------------------------- | -------------------------------------------------------------------------------------- |
| `-c, --config <file>`      | Input TOML or JSON configuration file (single mode).                                   |
| `-b, --batch <dir>`        | Compile every `.toml`/`.json` under a directory (raw outputs).                         |
| `-o, --output <path>`      | Output file (single; default `<input-stem>.tprm`) or directory (batch, required).      |
| `--fulluid <hex>`          | Target fullUid (e.g. `0x000100`): stamp the v3 payload prelude.                        |
| `--constraint-rows <path>` | Write the payload's constraint rows (JSON) for the on-board table (needs `--fulluid`). |
| `--verify <file>`          | Compare generated bytes against an existing file instead of writing.                   |
| `--hexdump`                | Print a hex dump of the generated bytes.                                               |
| `--pin-spec <manifest:S>`  | Error unless the walk's layout hash equals struct `S`'s spec hash in the manifest.     |

`--pin-spec` is the build-time rail for raw (preludeless) products:
sequence binaries carry no stamped hash for their reader to check, so
the sequence compile rule pins them against the ActionComponent spec --
a value file whose names, order, sizes, or total diverge from the
struct fails the build with both hashes named.

Batch outputs are raw (a directory carries no per-file fullUid); stamp
component payloads individually or through the build's packing manifests
(`cmake/apex/Tprm.cmake`), which pass each entry's fullUid from
`tprm.manifest`.

## Input Format

Each field entry specifies `type`, `size`, and `value`. Fields are serialized
in declaration order. Metadata keys starting with `__` (e.g. `__note__`) are
skipped. All multi-byte values are little-endian.

Optional constraint keys per numeric field -- `min`, `max` (inclusive),
`allowed` (explicit value list), `step` (granularity from `min`) --
declare the legal range: cfg2bin refuses to serialize a value outside
them (array elements inherit the parent's keys). Constraint keys are
authoring metadata only; they change neither the serialized bytes nor
the layout hash.

### Supported types

| Type     | Sizes      | Notes                                 |
| -------- | ---------- | ------------------------------------- |
| `uint`   | 1, 2, 4, 8 | Unsigned integer, little-endian.      |
| `int`    | 1, 2, 4, 8 | Signed integer, little-endian.        |
| `float`  | 4, 8       | IEEE 754 float/double, little-endian. |
| `bool`   | 1          | Serialized as 0 or 1.                 |
| `char`   | 1          | Single ASCII character.               |
| `string` | N          | Fixed-size, null-padded.              |
| `array`  | N          | Requires `element_type`.              |
| `struct` | N          | Requires nested `fields`.             |

### Example TOML input

```toml
[MyTunableParams.gainP]
type = "float"
size = 4
value = 2.0

[MyTunableParams.gainD]
type = "float"
size = 4
value = 1.5

[MyTunableParams.maxThrust]
type = "float"
size = 4
value = 200.0
```

| ---- | ----------------------------- |
| 0    | Success.                      |
| 1    | Parse or serialization error. |

## Examples

```bash
# Component payload: v3 prelude stamped for the target fullUid
cfg2bin --config configs/my_params.toml --output build/my_params.tprm --fulluid 0x00D200

# Sequence/blob: raw serialization, no prelude
cfg2bin --config toml/rts/rts_001_noop_sweep.toml --output 001.rts

# Batch-compile a directory of sources (raw outputs)
cfg2bin --batch ./configs/ --output ./binaries/
```

### Loading in C++

Component payloads load through the verified reader, which checks every
prelude field before the body reaches the params struct:

```cpp
#include "src/system/core/infrastructure/system_component/posix/inc/TprmPayload.hpp"

MyTunableParams params;
const auto CHECK = system_core::system_component::readTprmPayload(
    "tprm/00d200.tprm", 0x00D200U, params);
if (CHECK != system_core::system_component::TprmPayloadCheck::OK) {
    // distinct verdict per failed check; component stays on defaults
}
```
